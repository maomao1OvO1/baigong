YAML ⇄ JSON 変換

K8s のマニフェストや CI の yaml を扱うときに。一般的な記法に対応：キーと値、ネストしたインデント、リスト、インラインの [a, b] / {a: 1}、コメント、ブロックスカラー。
アンカーや複数ドキュメントなど未対応の記法は行番号付きでエラーにします。一見正しい設定ファイルが実は間違っている、という状態が最も危険だからです。

すべてブラウザ内で処理。送信も保存もしていません。

よくある質問

アンカーや複数ドキュメントに対応しない理由は？

設定ファイルでは稀でありながら、パーサーが数倍複雑になります。中途半端な対応で誤った結果を返すより、明確にエラーを出す方が安全です。

コメントは保持されますか？

いいえ。JSON にコメントは無いため失われます。必要な場合は変換後に手作業で戻してください。
