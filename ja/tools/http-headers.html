HTTP レスポンスヘッダーの解説

「なぜ古いままなのか」「なぜ Cookie が捨てられるのか」の答えはヘッダーにあります。ただし略語が読めればの話です。
レスポンス全体(ステータス行を含む)を貼り付ければ、各ヘッダーに平易な説明が付き、最後に不足しているセキュリティヘッダーが並びます。

よくある質問

ページが古いままです。どのヘッダーを見ればよい？

まず Cache-Control、次に Age と ETag です。max-age は「何秒間新鮮か」、no-cache は「使う前に毎回確認」、no-store は「保存しない」、Age が大きい場合は CDN に載っていた古いコピーを読んでいます。immutable は「max-age の間は再確認しない」で、バージョン付き URL の長期キャッシュがこれに依存しています。

セキュリティヘッダーを点検する意味は？

欠けていてもエラーもログも出ないからです。気づかないうちに防御が 1 層減ります。HttpOnly の無い Cookie はページ上のどのスクリプトからも読めます(XSS で注入されたものを含む)。Strict-Transport-Security の無いサイトは、初回アクセスで平文 HTTP に落とされる余地が残ります。

「解説がありません」と出たのは不具合？

いいえ。本ツールは収録済みの一般的なヘッダーだけを解説し、それ以外はそのまま表示します。知らないヘッダーにもっともらしい説明をでっち上げるより、知らないと言うほうが誠実です。
