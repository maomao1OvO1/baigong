よくある質問

対応しているキーワードは？

`type`（配列形式を含む）、`required`、`properties`、`items`、`enum`、`minimum`、`maximum`、`minLength`、`maxLength`、`pattern`、`minItems`、`maxItems`、そして `additionalProperties: false` です。実務の検証の大半をカバーします。`$ref` は解決せず、`format`（email や date-time）の意味的な検証も行いません。

schema に $ref があるとどうなりますか？

結果に「この部分は検証していない」と**明示**します。黙って通すことはしません。理解できない規則を飛ばす検証器は、検証器が無いより有害です。データは問題ないと誤解し、実際には何も確認されていないからです。

エラーにパスを付けるのはなぜ？

入れ子の配列を含む文書では「型が違います」だけでは探す場所が分からないからです。`data.items[2].price` のようなパスがあれば、5 分の探索が 1 行の修正になります。
