TOML → JSON

TOML は「1 行 1 設定」に見えますが、`[a.b]`、`[[items]]`、`a.b = 1` に出会うと事情が変わります —— 同じ「所属」を表す 3 通りの書き方です。
設定ファイルを貼り付けると、実際の入れ子構造が JSON で見えます。値の型は書かれたまま保ちます。

すべてブラウザ内で処理。送信も保存もしていません。

よくある質問

`[a.b]` と `a.b = 1` の違いは？

違いはありません。どちらもキーを a というテーブルの下に置きます。ドット記法は短いだけの書き方で、同じファイル内で混在させると「同じテーブルのつもりが 2 つになる」典型例になります。JSON にすればそれが一目で分かります。

日付が数値にならずテキストのままなのはなぜ？

JSON に日付型が無いからです。`2026-10-14T09:30:00Z` をタイムスタンプにすると、タイムゾーンのずれが黙って落ち、読み方も変わります。原文を保てば失うものはありませんが、誤った変換は見つけにくいまま残ります。

複数行文字列やコメントは扱えますか？

扱えます。三重引用符（`"""` と `'''`）は改行を保ち、`#` コメントは配列の途中にあっても無視します。なお**引用符の中の `#` はコメントではなく内容**です —— 正規表現でこの形式を処理すると、たいていここで崩れます。
