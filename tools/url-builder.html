FAQ

Should spaces be encoded as %20 or as +?

It depends on where the value lands. In a query string parsed as application/x-www-form-urlencoded, + means a space. Everywhere else — path segments, fragments, and APIs that decode by hand — + is a literal plus sign. The toggle is there because only the receiving side knows which convention it follows.

Why was a parameter already in my URL not re-encoded?

On purpose. Decoding and re-encoding is not a round trip: a + in an existing value turns into a real space, and an already-encoded value gets double-encoded, which breaks signatures and tokens. Existing parameters are passed through byte for byte; only the ones you add are encoded.

Which characters actually need encoding?

Reserved ones: & separates parameters, = separates key from value, # starts the fragment, ? starts the query, % introduces an escape. Space, plus and non-ASCII characters are also unsafe in practice — some servers, proxies and log pipelines cut a URL at the first one they dislike. This tool flags any value containing them.
