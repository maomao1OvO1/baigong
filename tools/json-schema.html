FAQ

Which keywords are supported?

type (including the array form), required, properties, items, enum, minimum, maximum, minLength, maxLength, pattern, minItems, maxItems and additionalProperties: false. That covers the great majority of real-world validation. $ref is not resolved and format (email, date-time) is not checked semantically.

What happens if the schema uses $ref?

The tool says so explicitly in the result instead of quietly passing it. A validator that silently skips a rule it does not understand is worse than no validator — you would conclude the data is fine when nothing was actually checked.

Why does the error list show the path?

Because in a document with nested arrays, "type mismatch" alone does not tell you where to look. A path like data.items[2].price turns a five-minute search into a one-line fix.
