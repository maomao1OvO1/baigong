FAQ

Will it change text inside my string literals?

No, and that is the whole point of scanning first. A condition like name = 'select * from users' holds data, not SQL — a plain search-and-replace for keywords would rewrite the stored value and quietly change what the query does. Tokens are classified before anything is touched.

Which SQL dialects does it understand?

It does not parse dialects at all — it formats by token type. That means it is safe for PostgreSQL, MySQL, SQLite, SQL Server and BigQuery alike, and also means it will not flag genuine syntax errors. Line comments in -- and # form, block comments, '' escaping and backtick or bracket quoting are all recognised.

Why does it not capitalise my table and column names?

Because that would change them. On PostgreSQL an unquoted identifier folds to lower case, and on a case-sensitive collation changing the case changes which table you hit. Only keywords are uppercased; identifiers are left exactly as written.
