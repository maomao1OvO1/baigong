FAQ

Which odd bits of .env syntax are handled?

An export prefix, single quotes (taken literally, as the shell does), double quotes (\n and \t escapes are honoured, and the value may span several lines), unquoted values with a trailing # comment, and keys containing dots. What is not done: variable interpolation — ${OTHER} is left exactly as written, because resolving it depends on the runtime environment.

The output still contains my real secrets. What should I watch out for?

That converting a file does not declassify it. The commonest leak path is a key pasted into a commit, an issue or a chat message after a conversion like this. If a key ever lands somewhere it should not, rotate it — deleting the message is not enough.

Why does the shell output wrap every value in single quotes?

Because that is the only form that survives every value literally. Without quoting, spaces split a value and $, backticks and ! get expanded by the shell; double quotes would still expand $. The one special case is an apostrophe, written as '\'' — which is why the output looks like that.
